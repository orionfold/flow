# Docs that stay true to the code

**For builders.** “My specs and README drift from the code, and I’m embarrassed to ship them.”

| For | What lasts | Needs |
| --- | --- | --- |
| Builders · indie hackers | Ownership, Quality | Flow Pro, Flow Publish |

1. **Add the repo folder; your git stays yours.** Flow reads the Markdown in place and leaves your commits alone. See [Using Flow ▸ Keep the folder portable](x-flow://handbook/Using%20Flow#Keep%20the%20folder%20portable).
2. **Proofread or expand a spec, change by change.** **Proofread** or **Expand with Sources** proposes edits, and **Review Changes** lets you keep or revert each part.
3. **Publish to GitHub Pages or a PDF.** **Publish** writes a site with navigation or a PDF with contents and page numbers.

**What lasts:** the docs are plain files in your repo, and every change to them was one you approved.
