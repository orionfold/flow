# Eleven resolved cases

**Fictional support digest for an invented product, Beacon Scheduling.** These are teaching notes, not customer records. Case IDs are identifiers and do not encode dates. All eleven cases were closed by 5 September.

### SK-01 · Access

Invitation opened in a browser signed into another work account. Resolved by choosing the invited account.

### SK-02 · Calendar sync

A newly added event was outside the connected calendar. Resolved by confirming which calendar was linked.

### SK-03 · Notifications

The user had muted a reminder category. Resolved by reviewing their own notification choices.

### SK-04 · Access

An expired invitation was reused. The workspace owner issued a new invitation through the normal product path.

### SK-05 · Time zones

A team member expected the organizer's time zone to control their own display. The agent explained that each person's display setting is independent.

### SK-06 · Calendar sync

An event was changed before a reconnect finished. Resolved after the user confirmed the connection and rechecked the event.

### SK-07 · Access

The user changed email addresses and looked in the old inbox. Resolved by confirming the invited address with the workspace owner.

### SK-08 · Notifications

A test reminder had no recipient enabled. Resolved by checking the saved reminder recipients.

### SK-09 · Calendar sync

Two calendars had similar names. Resolved by selecting the intended calendar and confirming with a test event.

### SK-10 · Access

An invitation was forwarded to a colleague instead of creating that colleague's own invite. The owner sent a separate invitation.

### SK-11 · Notifications

The user expected an email when only in-app reminders were enabled. Resolved by choosing the required delivery channel.
