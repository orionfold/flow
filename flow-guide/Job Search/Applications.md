## About these inputs

Fictional designer search, as of 2 September 2026. The one source file you edit. Each **Applications** row is a source record; [[Job Search]] redraws its tracker and timeline from those saved rows. **Prep** holds the accompanying checklist. Edit either table with its **Open in the table editor** control.

## What each field means

| Field | What it is |
| --- | --- |
| `company`, `role` | Who and what. Keep the role as the posting names it. |
| `stage` | Where it is: `Applied`, `Phone screen`, `Take-home`, `Onsite`, `Offer`, `Rejected`, `Withdrawn`. The timeline colours by it. |
| `applied` | The date you applied. The timeline's bar starts here. |
| `next_step`, `next_date` | The next thing that happens and when. Only active applications enter the next-action timeline. A past date means review the recorded next step; closed applications are history, not owed follow-ups. |
| `contact` | Who you are talking to. |
| `notes` | One line. Quote it if it has a comma. |
| `target_role`, `target_locations` | What you are looking for. Kept at the top so the page can say it. |

## Make it yours

- **Add an application.** Choose **View ▸ Edit Table** and add a row in **Applications**, then save. The complete tracker reads that record; the active timeline includes it only while its stage is active.
- **Move it forward.** Edit `stage`, `next_step` and `next_date` after every call. The morning's Briefing shows the exact diff, so the week's movement is a diff you can read.
- **Close it.** Set the stage to `Rejected` or `Withdrawn`; keep the line. The pattern across closed applications is worth having.

The six applications above are examples with real companies and made-up dates and stages. Replace them with yours.

`resume_version` records the exact local version actually sent; `not recorded` is an evidence gap. A folder inventory cannot establish a submission. Retain posting URLs, interview notes and sent versions in this workspace; do not infer them from a filename.
